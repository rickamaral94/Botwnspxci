# 2026-11-24 — Amaral.14: medições para o agente do Turnip (binds de offset; a geração de quadros separada da máscara)

## Por quê

- **Binds só de offset.** O agente do Turnip (PR #3) confirmou: um `vkCmdBindDescriptorSets` que só muda os offsets
  dinâmicos custa tanto quanto um set novo. O Turnip aloca e copia um set reservado novo, regrava todas as bases
  bindless e emite `SP_UPDATE_CNTL(gfx_bindless = 0xff)`, que invalida o cache de descritores dos 8 sets.
  - Para decidir um lab no driver (invalidar só os sets cujo endereço mudou), ele pediu o trace (drawCount e tempo do
    G-buffer) e a proporção de binds só de offset contra binds de set novo.
  - Do lado do app, ele indica push constants (256 bytes no Turnip) para as constantes por draw, e desaconselha um UBO
    grande indexado no shader.
- **A linha "framegen: HUD mask"** somava a geração inteira do LSFG (Amaral.13, seção "Resultado no Odin").

## O que mudou

- A linha `[vk] t=…` (a cada 2 s) diz quantos dos binds de set foram só de offset:
  `… pipe N sets (M only offsets)`. "Só offset" = os mesmos dois sets e o mesmo layout já ligados, com outros offsets
  dinâmicos.
- Um marcador `framegen: generation (LSFG) and the queue between` logo depois da máscara do HUD. Na tabela por passe,
  a máscara e a geração saem separadas (commit `ed568a7`).
- versionCode 52, `0.4.11-beta-amaral.14`.
